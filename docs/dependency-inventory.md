## 1. 位置づけ

- `Cargo.lock` の依存が、取り下げ済みでないか・所有者が 1 人でないかを、日付つきで記録する手順を定める
- 決定 D-58 は、次の 3 点を決めた
  - 時期: 初回公開の前と、リリースごと
  - 対象: 直接の依存と、取り下げ済みの crate・所有者が 1 人の crate
  - 記録: 結果に日付をつける
- あわせて D-58 は `yaml_serde` を維持して版を固定すること（PACK-47）と、L2 の配布物のサーバに `miniserve` 0.35.0 を使うこと（DLV-18）を決めた
- 棚卸しの結果、依存を変える必要が出ても、本タスクでは依存を変えない。事実を記録して TASK-18 に戻す
- CI・`make check`・lefthook には組み込まない。通信が要り数分かかるうえ、失敗したら止めるガードにする変更は人間の承認点だからである

## 2. 手順

```bash
make inventory-deps                          # 直接: node tools/inventory-deps.mjs。通信が要る（数分）
node tools/inventory-deps.mjs --format json  # 機械可読の出力
make test-inventory-deps                     # スクリプト自体の回帰テスト（通信なし）
```

1. 初回公開の前と、リリースごとに `make inventory-deps` を流す。標準出力は結果だけで、進行状況は標準エラーに出る
2. 終了コードを読む

    | コード | 意味 | 次の行動 |
    |---|---|---|
    | 0 | 取り下げ済み・registry に無い版・crates.io 以外の source・古い例外のいずれも無い | 結果を 4 節に追記する |
    | 1 | 上のいずれかがある（要約の「要確認」に出る） | 結果を 4 節に追記し、依存は変えずに TASK-18 に戻す |
    | 2 | 棚卸しを完了できない（通信の失敗・5xx・タイムアウト・壊れた JSON・checksum の不一致など）。標準出力は空 | 原因を直して流し直す。部分的な結果は記録しない |

3. 標準出力の Markdown を、本文書の 4 節の先頭に日付つきで追記する（追記専用。新しいものを上に置く）。基点（実行日・コミット・`Cargo.lock` の SHA-256・Node の版・取得先）は出力に含まれる
4. 3 節の照らし合わせを、その時点の `Cargo.toml`・`Cargo.lock` で確かめ直し、結論を添える

### 判定の規則

- 取り下げ済みは、`Cargo.lock` の版が sparse index で `yanked` かどうかで決める。index の `cksum` が `Cargo.lock` の `checksum` と一致しなければ 2 にする
- 「所有者 1 人」は、crates.io の所有者のうち user がちょうど 1 で team が 0 のことである。結果の注記と要約に記録するが、終了コードは変えない。2026-10-19 の実測では 66 件中 32 件が該当し、失敗にすると常に 1 になって信号にならないためである。依存を変えるかの判断は、記録を見て人間が行う
- 決定で維持を認めた crate は、`tools/inventory-deps.mjs` の `ACKNOWLEDGED_SINGLE_OWNER` に理由つきで載せる。増やすときは決定（D-n）を根拠に書く。`Cargo.lock` に無い名前が載っていれば古い例外として 1 にする
- 最新版・最終更新日は参考の列で、合否には使わない。継続の目安として人が読む
- 所有者の login 名など個人に関わる値は出力しない（数だけ）

`yaml_serde` の現況（2026-10-19、4 節の表の行）。`docs/testing.md` の 5.127 が未確認としていた点への答えである。

- 所有者は user 1 人・team 0。取り下げ済みではない
