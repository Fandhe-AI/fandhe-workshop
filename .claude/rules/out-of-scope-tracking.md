# 実装対象外の追跡規約

## 目的

実装・レビュー中にスコープ外と判断した事項を放置しない。
後で埋もれるのを防ぐため、発見したタイミングで Issue に記録して追跡可能にする。

## フロー

1. **検出**: 実装・レビュー中にスコープ外と判断した事項を控える（場所は `パス:行番号` で残す）。
    subagent は自分で起票せず、結果の報告に含めて main へ返す
2. **既存 Issue の確認**: キーワードは変数に入れ、クォートして渡す

    ```bash
    gh issue list --search "${KEYWORD}" --state open
    ```

3. **ユーザーに承認を得る**: 既存 Issue への追記か、新規起票か、記録しないかをユーザーと確認する
4. **記録**:
    - 既存 Issue がある場合は、コメントで追記する

        ```bash
        gh issue comment "${ISSUE_NUMBER}" --body "$(cat <<'EOF'
        （本文をここに記述）
        EOF
        )"
        ```

    - 存在しない場合は、`create-issue-tree` または `create-issue` で適切な親 Issue の配下に起票する
5. **元の PR・レビューに切り出し先を記録**: コメントまたは PR 本文に、切り出し先の Issue 番号を記載する

## 記録する内容

- 何が問題か・どこにあるか（`パス:行番号`）
- なぜ今回の範囲に含めないか
- 分かっている場合は、対処の方向性と影響範囲

## 注意

- ユーザーの承認なしに Issue を起票・コメントしない
- スコープ外の修正を現在の PR に混入させない（別 Issue・別 PR で対処する）
- 本リポジトリは public。Issue に秘密情報や、未修正の脆弱性の詳細を書かない（`.claude/rules/security.md`）
- 検証を通すために必要な修正は、スコープ内として扱う（`make check` が通らない状態で残さない）
