# 既知の不足（忠実さの限界）

エンジンの語彙では表せず、回避で書く範囲の一覧です。教材の作成者が「書けない」と迷ったときに、限界と回避を
引ける場所として置きます。語彙ではなく実行時の振る舞いの限界で、使い方で避けるもの（SAVE-12 など）も同じ形で記録します。

- ID は、公開の資料の ID（H-3・G-4）か、仕様の要件の ID（AUTHOR-13・FEND-22・SAVE-12 など）を使います。仕様は private の submodule にあるため、本文は転記せず ID で参照します
- 公開の資料の整備（TASK-411）で、PoC の記録で名指しされた不足のうち、今のエンジンで状態を確かめられたものを追記しました（2026-10-20）。確かめられなかった ID は、末尾の「確かめていない ID」に書きます
- 解消した ID も消さずに残し、状態の欄に解消した決定・タスクを書きます。PoC の記録の ID を引いたときに、たどれるようにするためです
- 記録は、書けなかった箇所・求める機能・ID の順に並べます

## H-3: 受講者が選んだ値を文中・経路に差し込めない

### 限界

- 状態変化（`put`・`remove`・`replace`・`set_attr`）の経路と値は、教材に書いた文字列そのものになります
- `${名前}` は、学習モジュールの引数をコンパイル時に置き換えるだけです。章の中に書いても置き換わらず、文字のまま残ります
- 受講者の入力の値は、規則の照合（`on.args` など）にだけ使われます。世界状態の経路や属性には入りません
- 拒否・問い返しの文面への差し込み（`{{input_head}}` など）は別の仕組みです。枠は閉じた集合で、世界状態には入りません
- 差し込みらしい欄（`value_from`・`path_from` など）を状態変化の語に足しても動きません。`on_enter` などでは未知の欄として `E-PARSE` になります。`rules[].outcome.effects` では読み込みを通過し、実行時に警告（`Event::Warning`）となって入力が拒否されます

### 理由

D-50（2026-10-12）で、足さないと決まりました。回避で書けていて、要件の不成立に直結しないこと、受講者の値を
経路に入れると、未信頼入力として守る範囲が広がることの二つが理由です。この限界は、忠実さの限界として受け入れています。

### 回避: 起こりうる入力を列挙する

候補ごとに規則を並べ、それぞれに固定の効果を書きます。

```yaml
rules:
  - id: r-alpha
    on: {command: make-item, args: {name: alpha}}
    outcome:
      kind: accept
      effects:
        - put: {path: work/alpha, attrs: {label: first}}
  - id: r-beta
    on: {command: make-item, args: {name: beta}}
    outcome:
      kind: accept
      effects:
        - put: {path: work/beta, attrs: {label: second}}
```

- 列挙にない値は、`not_in_this_step` で拒否され、世界状態は変わりません
- 引数の条件を持たない規則を最後に置けば、列挙にない値も受け付けられます。ただし効果は固定値で、入力の値は入りません
- 具体的な規則から先に書いてください。先の規則が後の規則を隠す（遮蔽）ことは `validate` が見つけません（`docs/pack-authoring.md` の「`validate` が見つけない欠陥」）
- 規則の `outcome.effects` に未知の欄を書いた場合、読み込み時には止まりません。実行時に入力ごと拒否され、世界状態は変わりません（fail-closed）。誤って差し込みの欄を書かないよう、`on_enter` などに置いた同じ欄が `E-PARSE` になることで確かめてください

## SAVE-12: 古いタブの保存の照合と書き込みが原子的でない

### 限界

- 同じ教材を同じブラウザの 2 つのタブで開くと、どちらも同じ保存先へ書きます。エンジンは、ページを開くたびに起動番号を書き、保存の直前に照合して、後から開いたタブがあれば古いタブの保存を止めます
- 古いタブが保存を試みると、そのタブの画面に「保存されていない」通知（`stale-notice`）が出ます（TASK-325 1/2）。出るのは保存を試みた後で、別のタブが開いた瞬間には出ません。文面は仮置きです
- 照合と書き込みは別の操作で、タブ間で原子的ではありません。古いタブが照合を通った直後（古いタブから見える起動番号が古い間）に別のタブが同じ教材を開くと、古いタブの保存が 1 回だけ届きえます
- この 1 回で、後から開いたタブの保存が消えることは通常ありません。後から開いたタブは、操作するまで保存しないためです（SAVE-28）。そのタブで操作すれば、その保存が上書きして残ります
- 残る影響は、後から開いたタブを操作しないまま再読み込みすると、古いタブの最後の 1 回分が見えることです
- 後から開いたタブの保存まで上書きするには、そのタブを開くことと最初の保存の両方が、古いタブの照合と書き込みの隙間に入る必要があります。最初の保存は人の操作の後の遅延保存か、ページを離れる直前の書き出しを待つため、通常は届きません
- 古いタブは、書いた直後にもう一度照合します。この再照合が他のタブの起動を見られるかは、実ブラウザでは確かめていません（未確認）。見られない場合も、古いタブの次の保存は、その前の照合で止まります
- 凍結されたタブや、長く塞がれたメインスレッドで隙間が広がるかは、2026-10-21 時点で確かめていません（未確認）

### 理由

- 起動番号を置く localStorage には、比べて書く操作（CAS）も排他もありません。WHATWG HTML の Web Storage 節は、"This specification does not define the interaction with other agent clusters in a multiprocess user agent, and authors are encouraged to assume that there is no locking mechanism." としています（作成者は排他の仕組みが無いと考えるべき、という趣旨）
- 排他の代わりの案は、どれも採りません。Web Locks は非同期で、ページを離れる直前の書き出しを守れず、保存の経路の大きな非同期化が要ります。IndexedDB の 1 つのトランザクションでは、localStorage への書き込みを守れません。世代つきの鍵は、保存の契約の版上げと SAVE-14 の変更が要り、仕様の決定が先に要ります
- 履歴を IndexedDB へ切り替えた後は、書き込みのトランザクションを照合と同じ同期の区間で作ります。範囲の重なるトランザクションは作成の順に処理されるため、隙間は非同期の完了までは広がりません。ただし、隙間が広がらないことと、競合そのものを防げることは別です。隙間の中で古いタブの書き込みが後のタブの書き込みより後に作られれば、古いタブが後に確定して上書きします
- 原子性を要件にする場合は、仕様の決定に回します

### 回避

- 同じ教材は 1 つのタブで開いてください
- 別のタブで開いてしまった場合は、古いタブを再読み込みしてください。再読み込みしたタブが新しい起動番号を取り、保存済みの履歴から続けます

### 根拠の試験

- `crates/web/tests/boot_guard.rs` の `限界_照合の後に別のタブが取得すると_1_回だけ書くが_後のタブの保存が残る`・`限界_照合の後に取得したタブが未操作なら_先のタブの_1_回分が残る`: 照合の読み取りの直後に別のタブの取得を割り込ませ、古いタブの 1 回分が届くこと、後のタブの保存が残ること、後のタブが未操作なら古いタブの 1 回分が残ることを固定します。試験の偽の保存領域にはタブ間の遅れが無いため、書いた直後の再照合が効きます
- 同じファイルの `限界_書いた直後の再照合が古い値を読んでも次の保存の照合で止まる`: 再照合が古い値を読む（効かない）場合を模し、古いタブの次の保存が照合で止まることを固定します
- 逐次の場面（照合の前に別のタブが開いている）で古いタブが書かないことは、同じファイルの他の試験と `tools/browser/stale-tab.test.mjs` が確かめます。隙間の競合そのものはブラウザ試験の対象外です

## SAFE-28: 「このまま保存する」の確認済みは再読み込みで失われる

「このまま保存する」で確認済みにした値は、そのページの実行中だけ有効です（`EngineHost` のメモリ上の形と指紋。保存先にも履歴にも書きません）。再読み込みの後は、保存した履歴に値が含まれていても確認済みではなく、次の変更の保存で再び警告が出ます。旧いエンジンが書いた値や、読み込んだ履歴ファイルに含まれる値を黙って確認済みにしないための、安全側の選択です（2026-10-21。TASK-164 3/3。`docs/testing.md` 5.183）。

- 警告と選択の文言・配置は仮置きで、確定は TASK-534 が持ちます

## JUDGE-24: 上限を超える貼り付けは Ctrl+Z で取り消せない

### 限界

- 入力欄の途中へ上限を超える文字列を貼ると、エンジンは貼った分だけを切って値を書きます（`crates/web/src/glue.rs` の `wire_paste_clip`）。既定の挿入を止め、`set_value` で値を書き、合成の `input` を発火させます
- このため、Ctrl+Z を 1 回押しても貼り付けの前に戻りません。2 回押しても戻らず、取り消しの履歴がまるごと消えます
- 上限ちょうどの欄へ貼り付けると、何も挿入されません。このとき Ctrl+Z を押すと、その前の操作が取り消されます
- 末尾への超過の貼り付けと、上限での打鍵も `set_value` を通ります。このため、同じく取り消しの履歴が消えると推測します（推論・未確認）
- 確かめたのは Chromium（Playwright・Linux）だけです（2026-10-21）。Firefox・Safari・実際の IME では確かめていません

### 理由

- 取り消しは対象外とし、限界として記録すると決めました（2026-10-21。#1667）
- 超過の印（案内と `inputOverLimit`）は、はみ出した 1 文字を欄の末尾に置き、`clamp_draft` がそれを切る書き戻し（`sync_draft` の `set_value`）で立てています。この書き戻しが、取り消しの履歴を消します
- `document.execCommand('insertText')` で書く案を、Chromium の試作で 3 通り試しました（2026-10-21）。末尾にはみ出し 1 文字を置く案と、2 回に分けて挿入する案は、取り消しが効きませんでした（後者は `input` が 2 件になります）。残す分だけを挿入する案は、Ctrl+Z 1 回で値と選択範囲が戻り、やり直しも効きましたが、超過の印が立たず、ブラウザ試験 J-1〜J-5 のうち 6 件が失敗しました
- 両立させるには、欄の値を通らずに印を立てる新しい経路（`RuntimeAction` など）が要ります。判定が 2 か所に分かれ、glue に新しい種類の操作が加わり（FEND-20）、部品の契約の版上げと spec の変更が要るため、範囲に見合わないと判断しました

### 回避

- 貼り付けを取り消したいときは、貼った分を手で消してください。上限を超えそうな長い文字列は、貼り付ける前に短くしてください

### 根拠の試験

- 切り捨ての位置は `tools/browser/input-limit.test.mjs` の J-1〜J-5 と `crates/web/tests/input_limit.rs` の `judge24_` が確かめます。取り消しは試験しません。試作の結果は `docs/testing.md` 5.189 の「既知の限界」に記録しました

## PACK-34: 書き出しを入力とする Step は達成にならない

### 限界

- `input: {kind: env_action, action: export}` を書いた Step は `validate` を通ります。しかし、今はどの操作でも達成になりません。この Step を置いた教材は、そこで先へ進めません
- 保存（`action: save`）の Step は、保存の成功で受付になります。チェックポイントの写しは達成の前の状態で控えるため、その写しへ復帰すると保存の Step に戻ります
- 保存・書き出しのボタンの画面は未実装です。保存の操作を受講者が行う入口は、2026-10-21 時点の画面にありません

### 理由

- 書き出しの成否は web が持ち、core には書き出しの成功を伝える `Op` がありません。結ぶには `Control` に新しい種類を足す必要があり、世代の表・`CONTRACT_VERSION`・契約サンプル・履歴の `ops` の形・書き出しの画面（TASK-531）に影響が及びます
- 本タスクは語と保存の結線までとし、書き出しの結線は別に扱うことにしました（2026-10-21。TASK-64 1/2）
- 保存の成功を受付にする結線は `crates/core/src/env_input.rs` に置きました。保存の分岐（`checkpoint`）は教材を読まない不変条件を持つためです

### 回避

- 書き出しを案内する Step は、`env_action` を使わず、別の入力（1 択の `choice` など）で達成にします
- 保存を入力とする Step は、`confirm: { kind: none, reason }` と組みます。画面に保存の入口が出るまで、実際の教材では使わないでください

### 根拠の試験

- `crates/pack/tests/env_action_input.rs` の `pack34_`（宣言の検査）と `crates/core/tests/env_action_save.rs` の `pack34_`（`pack34_export_step_is_not_achieved_by_save` が、書き出しの Step を保存で達成にしないことを固定する）。記録は `docs/testing.md` 5.209

## PACK-51: モジュールの先頭の Step を省けない

限界: `use` で呼んだ実体は、必ずモジュールの先頭の Step から始まります。呼び出しごとに先頭の Step を省くことはできません。

理由: 先頭の Step を省ける語は足さず、作成者の規約として受け入れると決めました（D-43、PACK-51・MOD-17 (a)）。決定の理由は記録にありません。

回避:

- 先頭の Step を振り分けの Step にします。その `next` に `when: {param: {name: <引数>, eq: "<値>"}}` を書き、引数で後ろの Step を飛ばします（例は `testdata/module-reuse-rounds` の `issue-to-merge` の `st-3-2` と `setup`）
- 省きたい Step そのものを先頭に置きません

注意: 飛ばした Step は IR に残り、遷移で通らないだけです。実行時に未着手のまま残り、途中開始の「省略」と区別されることは、エンジンの側の担当で、本試験は見ません（MOD-17 (b)）。

- `param_types` を書かない引数は、従来どおり任意の文字列で通ります（加算の変更のため）
- `condition.param` の `eq` に書く値が宣言した型・範囲に入るかは検査しません。入らない分岐は到達しないだけです
- `int` は 10 進の正準形（`"01"`・`"+1"`・`"-0"` は不可）で、`i64` の範囲だけです

根拠の試験: `crates/pack/tests/module_first_step_gap.rs`・`crates/pack/tests/module_arg_types.rs` の `pack51_`。

## ART-18: 文書ビューの本文の表示の限界

限界: 製品の左エリアが練習データの本文を出すのは、文書のビューを選んでいて、そのビューが `body: shown` で、行の要素に `fixture` があり、その ID が IR の `fixture_docs` にあるときだけである。次の場合は本文の区画（`data-testid="artifact-doc-body"`）を出さない。出せない理由の文も出さず、経路の行だけが残る。

- `body` を省略した・`hidden` にした文書ビュー
- `fixture` を持たない要素（`put: {path: ...}` だけ）の行
- 文書以外のビューを選んでいるとき（文書に戻すと再び出る）
