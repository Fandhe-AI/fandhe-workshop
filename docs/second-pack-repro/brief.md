# 作者への要件（第 2 教材「レビューの頼み方」）

この文書は、作者（別のコンテキストの AI エージェント）に渡した要件の要約です。出所は、製品の第 2 教材の要件の記録の 1〜6 節です。答え（拒否の ID・規則の ID・文面・ファイル構成・件数）は含めていません。private の仕様の本文は転記せず、ID だけで参照します。

## 目的

公開の資料（`public/`）と実行ファイル（`bin/fandhe-pack`）だけで、形式 B の教材パックを `pack/` に書き、`validate` と `test` を通してください。エンジンのソースは見ません。

## 題材

レビューを頼むときに、相手・頼む範囲・見てほしい点・期限を選び、依頼文の下書きを整える教材です（AR-1・SECOND-5）。架空の場面は、ログイン画面の入力チェックを直した後でレビューを頼むところです。社内固有の情報は含めません。所要は 10 分程度と本文に書きます。

## 制約と設定値

| 制約 | 設定値 |
|---|---|
| 選択肢（`choice`）と画面操作（`ui_action`）だけで進む。コマンドも自然文の入力も使わない | `input_field: hidden` |
| 左は文書のビューだけ。世界状態の一覧とビューの切り替えを出さない | `world_list: hidden`・`view_tabs: hidden`・全 Step が文書のビューだけ |
| コマンドを持たない | `command_prefix: ""`・`commands: {}` |
| Claude Code 風の外観を使わない | `pack.appearance.theme: reading` |
| 章は 1 つ、開始点は 1 つ。GitHub 風のビュー・6 工程・2 周・掲示板・シェル風の操作を使わない | 掲示板の語彙なし |
| 形式 B で書く | `workshop.yaml`・`chapters/<章>/chapter.yaml`・本文の Markdown・`tests/playthrough.yaml`・練習データ |

## 学習目標（2 つ）

- LO-1: 読む人が迷わないように、宛先と頼む範囲を絞れる
- LO-2: 見てほしい点と期限を、1 つに決まる形で書ける

## Step（8 つ）

| ID | 題 | 入力 | 確認 | LO | 変わる行 |
|---|---|---|---|---|---|
| st-1 | 状況を確認する | `choice`（1 択「下書きを作り始める」） | `answer` | LO-1・LO-2 | 状態 |
| st-2 | 宛先を選ぶ | `choice` | `point_at` | LO-1 | 宛先・状態 |
| st-3 | 頼む範囲を選ぶ | `choice` | `answer` | LO-1 | 範囲・状態 |
| st-4 | 見てほしい点を選ぶ | `choice` | `answer` | LO-2 | 見てほしい点・状態 |
| st-5 | 空いている行を探す | `ui_action` | `answer` | LO-2 | 期限 |
| st-6 | 期限を選ぶ | `choice` | `point_at` | LO-2 | 期限・状態 |
| st-7 | 送る前に見直す | `choice` | `answer` | LO-1・LO-2 | 状態（見直し済み） |
| st-8 | 送る（最終 Step） | `choice` | `answer` | LO-1・LO-2 | 状態（送信可） |

文書のビューは 5 行（状態・宛先・範囲・見てほしい点・期限）です。選ぶたびに該当の行の内容が変わり、変わった行には変化の印が付きます。

## 誤答への応答（8 場面）

次の場面を、拒否の分類の名前（資料にある語）つきで書いてください。拒否のあと、左の行は変わりません。

1. 確認（`answer`）の誤答の解説
2. 規則による拒否（宛先に「チーム全員」を選ぶ）
3. `point_at` の外れ
4. `ui_action` で、すでに埋まった行を押す
5. 条件つきの拒否（差分と関連テストを範囲に選んだ後で「明日の 17 時まで」を選ぶ）
6. 期限に「できるだけ早く」を選ぶ
7. 見直さずに送る
8. 送った後に「直す」を選ぶ

## 教材テスト

- 模範解答を 2 通り書く。宛先・範囲・見てほしい点・期限の選び方を変える
- 誤答の各場面を誤入力として書く。件数は指定しない
- `bin/fandhe-pack validate pack` が診断 0 件、`bin/fandhe-pack test pack` が終了コード 0 になること
- 最後に `bin/fandhe-pack compile pack -o pack/tests/ir.json` を実行して IR を残す

## 報告の様式

- `validate`・`test` の出力の件数（模範解答 a/a、誤入力 b/b）
- 書けなかった箇所。エンジンを直す提案はしない。`known-gaps.md` の ID（無ければ「資料に無い不足」）を添える。条件つきの拒否を誤入力として通せないなどの場合も、そのまま書く
- 読んだファイルと実行したコマンドの一覧（作業場所の外に触れていないことの確認のため）
