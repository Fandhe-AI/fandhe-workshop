# 参照元の版を上げる手順書

```text
手順書の版: 1
決定日: 2026-10-22
状態: 固定（契約）
```

## 1. 位置づけと版

- 本文書は、教材の参照元（上流の repo）の版を上げるときの手順を 1 か所に固定する（TASK-182 2/2、VER-15）。連動する要件は UMAP-5・UMAP-13・BUILD-26、根拠は R-35・W-34・C-12・C-18 である
- 洗い出しの道具は `tools/upstream-impact.mjs`（TASK-182 1/2）である。本文書は、その道具を使う順番と、公開の前に人が行う確認を決める
- エンジン（crate）は対応表を持たない（D-70）。対応表と確認の記録の置き場は教材 repo である。本 repo は様式だけを定め、実際の記録は持たない
- 人の確認の方法は D-78（2026-10-22。親 issue #493 のコメントに要約がある）に従う。5 つの公開前の確認のすべてで、最終の承認はユーザー（リポジトリの管理者）が行う。AI と機械の照合は、承認の前の走査と記録づくりに使う
- 仕様は private のため、本文を転記せず ID だけで参照する
- 版の規則: 手順を変えるときは版を上げ、変更履歴に記録する
- 文書の形（版の欄・節の順・固定の文・実在するパス）は `crates/pack/tests/upstream_bump_procedure_doc.rs` が見る。正は本文書である

## 2. 前提

- 教材 repo に次の 2 つがあること
  - 対応表の CSV（版 1。必須の列は `scope,step,ref`、任意の列は `path` と `lines`）。置き場の最終の形は TASK-717 が決める
  - パック全体の `refs`（参照名と commit）
- 道具は Node で実行する。通信は要らない
- 本文書の例のコマンドは、変数をクォートして書く。値を `eval` やシェルの組み立てに渡さない

## 3. 参照版の再取得と差分の抽出

- 上流を最新の状態で取り直す。旧版と新版は、ブランチ名ではなく commit SHA で固定する（取得した内容の完全性を記録に残すため）
- 固定した 2 つの SHA の間で、`git diff --name-only "$OLD_SHA" "$NEW_SHA"` を取り、`ref,path` の CSV（ヘッダ `ref,path`）にする。`ref` は教材の `refs` の参照名である
- 差分の CSV は一時ディレクトリに置き、教材 repo にコミットしない
- 参照名の全体が変わった場合（repo の移転など）は、差分の代わりに `--changed <参照名>` を使う

## 4. 影響する Step の洗い出し

1. `fandhe-pack vocab "$PACK_DIR"` の標準出力を、一時ディレクトリに保存する
2. 次を流す

    ```text
    node tools/upstream-impact.mjs --map "$MAP" --changes "$CHANGES" --vocab "$VOCAB"
    ```

3. 終了コードごとに進める

| 終了コード | 意味 | 対応 |
|---|---|---|
| 0 | 列挙できた（0 件を含む） | 出力の一覧を見直しの対象にする |
| 1 | 教材に無い Step を指す行が対応表にある | 対応表を直す。直してから 1 に戻る |
| 2 | 入力の形が不正（標準出力は空） | 入力を直す。先へ進まない |

- **0 件でも、人の確認（6 節）は省かない**。道具は表に書かれた対応だけを見るため、表に無い場面は拾えない
- 道具の限界: 行番号では照合しない（版を上げると行がずれるため）。`path` が空の行は参照名の全体に依拠する。表の形は TASK-717 の決定で版 2 になりうる

## 5. 教材の更新と教材テスト

- 洗い出しで挙がった Step と、`refs` の版を直す。上流の文面は写さず、リンクで出典を示す（D-11）
- **教材テストを通す**。2026-10-22 時点で、その意味は次のとおりである
  - 教材 repo の試験（対応表の Step ID と `vocab` の突き合わせなど。PACK-46）が CI で通る
  - `fandhe-pack compile "$PACK_DIR"` が診断 0 件・終了コード 0 で通る
  - `fandhe-pack test` は TASK-404 の実装の後に加える
- 終了コード 2 を合格として扱わない。未実装のコマンド（`error: fandhe-pack <cmd> is not implemented yet`）も同じである（fail-closed）
- 教材テストが 1 つでも通らなければ公開しない

## 6. 公開前の人の確認と記録

- 公開直前に、人が対応表の 11 場面（UMAP-13）のすべてを、新しい参照版と照らして読む。洗い出しの一覧は注意を向ける先を絞るためのもので、全場面の確認の代わりにしない
- **公開前に人が対応表を確かめて記録を残す**（R-35）。最終の承認はユーザー（リポジトリの管理者）が行う
- AI の代わりの確認（D-28）は、この最終の承認を満たさない
- 記録の様式

| 欄 | 書く内容 |
|---|---|
| 参照名 | 上流の参照名 |
| 旧版・新版 | commit SHA |
| 洗い出しの結果 | 件数と終了コード |
| 教材テストの結果 | CI の実行へのリンク |
| 確かめた場面 | 11 場面のうち確かめたもの |
| 確かめた人 | 名前 |
| 日付 | YYYY-MM-DD |
| AI の使用 | 有無・用途と、検証した人 |

- 記録は教材 repo の更新 PR（または記録のファイル）に残す
- 記録に、秘密情報（トークン・認証情報入りの URL など）と上流の文面を書かない

## 7. AI の生成物の扱い

- AI は草案・影響調査・更新 PR の作成に使ってよい（W-34、BUILD-26）
- **生成物を無検証で公開しない**。公開してよいのは、教材テストを通り、かつユーザーがレビューして承認した後だけである。時期は更新ごとである
- AI が書いた記録は、人が確かめた記録の代わりにしない

## 8. 公開の条件の確認の一覧

- [ ] 旧版・新版を commit SHA で固定した（3 節）
- [ ] 洗い出しを流し、終了コードが 0 である。1・2 を残していない（4 節）
- [ ] 一覧の Step と `refs` を直した。上流の文面を写していない（5 節）
- [ ] 教材テストが通った（5 節）
- [ ] 人が対応表の 11 場面を確かめ、記録を残した（6 節）
- [ ] 最終の承認をユーザーが行った（6 節）
- [ ] AI の生成物を、検証せずに公開していない（7 節）

## 9. 限界と未決の事項

- 参照元の版の更新頻度（Q-14）は未決である
- 出典の検査（TASK-132）は教材 repo のタスクで、まだ無い
- `refs` の置き場（TASK-717）は未決である
- `fandhe-pack validate`・`test` は未実装である
- 洗い出しの道具は CI に組み込んでいない（人間の承認点）
- 公開前の確認そのもの（記録の作成と承認）は、本文書の対象ではなく人が行う
