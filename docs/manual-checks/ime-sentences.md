# 日本語入力の確認表（試験文 30 文）

macOS の日本語入力と Chrome で、変換の確定と送信の Enter を取り違えないかを人が確かめる表です。
対象 ID は BUILD-18・TERM-4・JUDGE-15・FEND-9（対応は [`README.md`](README.md)）。
文は架空のもので、上流の文面を使っていません（D-11）。

## 内訳

漢字かな混じり 10（S-01〜S-10）、カタカナ・英数の混在 5（S-11〜S-15）、記号・句読点 5（S-16〜S-20）、
候補の一覧から選んで確定 5（S-21〜S-25）、確定の前に Esc で取り消し 3（S-26〜S-28）、
Shift+Enter を含む複数行 2（S-29〜S-30）。

## 場面

教材の CH-1 の最初の Step（`?start=s-1-1`。「コマンドを送る（/help）」）で行います。この Step は自由な文を
受け付けずに断るため、文を何度送っても Step が進まず、30 文を同じ場面で続けて試せます。

- **送られた**: 右のログに、送った文の行が 1 件増えます（続いて断りの応答の行が出ます）
- 断られた文は入力欄に残り、全体が選ばれた状態になります。次の文はそのまま打てば置き換わります
- 右のログは改行を空白のように見せます（2026-11-18 の観察。記録には改行が残り、見え方だけの不具合。#2189）。複数行の文の改行は、送る前の入力欄で見ます

## 判定の規則（1 文ごと）

| 種類 | 合とする条件 |
| --- | --- |
| S-01〜S-25 | 変換を確定する Enter で、右のログが増えない（誤送信 0）。続けて押す Enter で、送った文の行がちょうど 1 件増える（送信漏れ 0） |
| S-26〜S-28 | 変換の途中の Esc で、右のログが増えず、停止・取り消しの行も出ない（停止 0）。入力欄が空になる |
| S-29〜S-30 | 1 行目の確定の Enter で送られず、Shift+Enter で改行が入り、2 行目の確定の後の Enter で 1 件だけ送られる |

確定した文字列が「期待の確定文字列」と違っても（辞書の学習で候補の順が違うなど）、送信の判定には影響しません。
違った場合はメモに書きます。

## 操作

1. 読みどおりにかなで打ち、Space で変換し、Enter で確定します。この Enter で送られていないかを見ます
2. もう一度 Enter を押し、右のログに 1 件だけ増えたかを見ます
3. S-21〜S-25 は、Space を何度か押して候補の一覧を開き、矢印キーで期待の文字列の候補を選んで Enter で確定します。
    文の後ろ半分（ひらがなのまま残す部分）は変換しません
4. S-26〜S-28 は、先に入力欄を空にしてから（Cmd+A → Delete）、読みを打って変換の途中で Esc を押します。
    Esc は 1 回だけ押します（変換していないときの Esc は、教材の取り消しの操作になります）
5. S-29〜S-30 は、「／」の前を 1 行目として確定した後に Shift+Enter、2 行目を確定した後に Enter を押します
