# 日本語スタイル

## 言語

- ユーザーへの応答・計画・報告は日本語で書く
- 技術用語・識別子・コマンド・ファイル名・ツール名は原語のまま書き、バッククォートで囲む
- 無理に訳さない（例: 「プルリクエスト」ではなく「PR」、「コミット」「フック」「ワークフロー」はそのまま）

## 文体

| 対象 | 文体 |
|---|---|
| ユーザーへの応答・`README.md`・`CONTRIBUTING.md`・`docs/glossary.md` | です・ます調 |
| `CLAUDE.md`・`.claude/rules/`・`.claude/agents/`・コード内コメント | である調（体言止め・箇条書きを使ってよい） |
| コミットメッセージ・PR タイトルの要約 | 日本語の「〜する」「〜を追加」など、簡潔な言い切り |
| スクリプトのエラー・usage の出力 | 英語（`error: ...` / `usage: ...`） |

同じファイルの中で文体を混ぜない。既存のファイルを編集する場合は、そのファイルの文体に合わせる。

## 表記

- 英数字と日本語の間には半角スペースを入れる（例: `Makefile は薄い入口`）。記号・括弧の前後には入れない
- 括弧は全角（`（）`）を使う。コード・コマンドの中は半角のまま
- 並列は中黒（`・`）、言い換え・補足は全角括弧で書く（既存の文書に合わせる）
- 日付は `YYYY-MM-DD` の絶対表記にする。「昨日」「先週」などの相対表記を文書に残さない
- 計測値・棚卸し結果には、計測した日付を添える

## 書き方

- 結論を先に書き、理由・詳細を続ける
- 一文に一つの内容を書く。長い条件は表か箇条書きにする
- 「なぜそうするか」を書く（規則だけを並べず、理由が分かれば例外を判断できる）
- 確認した事実と、推測・未確認の点を分けて書く
- 失敗・未実施は、そのまま書く（成功したように要約しない）
- 絵文字は使わない
